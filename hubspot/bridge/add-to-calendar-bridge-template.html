{# ============================================================================ Free Class Add to Calendar Bridge -- page template (HubL + JS) Author: Jibril Sulaiman Date: 2026-10-19 (v1.0.0) Deploy: HubSpot Design Manager, as a page template named "Free Class Add to Calendar Bridge". One landing page uses it: https://www.example.com/add-to-calendar (Settings: no index, not in sitemap). Use the portal's primary domain: the HubSpot MCP connector can only publish pages there. WHAT IT DOES Reads one Free Class Configuration record (object 2-12345678) and turns it into a calendar entry: ?service=google Google Calendar's new-event screen, filled in ?service=outlookcom Outlook.com's new-event screen, filled in ?service=yahoo Yahoo Calendar's new-event screen, filled in ?service=outlook downloads Free-Class.ics (Outlook desktop) ?service=ical|apple downloads Free-Class.ics (Apple Calendar, iPhone) The record is picked by ?id= (what the page module sends) or ?class= (readable links for emails and texts), for example https://www.example.com/add-to-calendar?class=topic-a&service=google WHY The HubSpot version of the Add to Calendar bridge on the GoHighLevel funnels. It replaces the AddEvent links on the confirmation and watch pages, so a new class means editing the config record only, with no AddEvent event to create and no Add Event ID to paste. What changed from the GHL version, and why: - The start time is the record's real datetime (7. Event Start Date and Time), stored in UTC. No "MM-DD-YYYY hh:mm" text to parse and no Eastern/UTC arithmetic, so EST/EDT cannot drift. - Every record value is written through |escapejs, so an apostrophe in a title can no longer stop the script. - The JavaScript sits inside a raw block, so HubL never touches braces inside the code (the GHL merge-tag trap). - Outlook.com and Yahoo open their own web calendars instead of downloading a file. - The .ics UID is fixed per record and start time, so adding the same class twice updates the entry in most calendars instead of doubling it. - A class that has already ended shows a message instead of adding a past event.
